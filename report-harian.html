Ringkasan Eksekutif

Hari ini dikerjakan modul Penerimaan Material Production — fitur yang menjembatani issue-out material oleh warehouse dengan konfirmasi penerimaan di mesin oleh operator produksi. Modul ini mencakup backend (API, service, migrasi), Flutter APK (scan tag + scan mesin + daftar penerimaan), dan web monitoring (halaman Inertia dengan live Echo).

Selain itu dilakukan pembersihan fitur container & foto inspeksi pada modul Incoming yang tidak terpakai dan menyebabkan status invoice selalu "pending".

Fitur Baru: Penerimaan Material Production

Alur baru di APK Material Tracker: setelah warehouse melakukan issue-out (scan tag material → release WO), operator produksi di lantai membuka APK, scan tag material yang sudah di-issue, lalu scan QR mesin tujuan. Sistem mencatat bahwa tag tersebut telah diterima di mesin tertentu pada jam tertentu. Tidak ada input qty — qty diambil dari dokumen issue.

Komponen yang Dibangun

Backend (ERP)

  • Migrasi — tabel production_material_receipts dengan kolom material_issue_item_id, tag, part_id, machine_id, received_by, received_at. Unique constraint (material_issue_item_id, machine_id).
  • Model — ProductionMaterialReceipt dengan relasi ke MaterialIssueItem, Part, Machine, User.
  • Service — ProductionReceiptService dengan validasi: tag harus sudah di-issue-out, mesin harus aktif, tidak boleh duplikat (tag + mesin yang sama).
  • API — POST /api/receipts/confirm dan GET /api/receipts?machine_id=. Authorization via permission stock.issue.
  • 8 test API — mencakup sukses, unknown tag, inactive machine, duplikat, list by machine, filter by date.

Web Monitoring (Inertia Vue)

  • Halaman Produksi → Penerimaan Material dengan filter mesin (dropdown) dan tanggal.
  • Tabel daftar penerimaan: tag, part, invoice, supplier, penerima, jam.
  • Statistik realtime dengan koneksi Echo (live update).
  • Indikator koneksi (connected/disconnected).
  • Link di module launcher Produksi.

Flutter APK

  • Model: ProductionReceipt, ReceiptConfirmation, ResolvedMachine.
  • Parser QR: ScannedMachine untuk label mesin.
  • Repository: ProductionReceiptRepository — confirm, receiptsByMachine, resolveTag, resolveMachine.
  • Provider: ReceiptConfirmNotifier + ReceiptListNotifier (Riverpod).
  • Screen: ReceiptConfirmScreen — alur 2 langkah (scan tag → scan mesin → konfirmasi).
  • Screen: MachineReceiptListScreen — daftar penerimaan per mesin.
  • i18n: Semua kunci baru dalam id/en/ko.

Pembersihan: Container & Foto Inspeksi

Fitur container (nomor kontainer, seal, ukuran) dan foto inspeksi (photo_front, photo_back, dll.) pada modul Incoming Arrival dihapus karena tidak pernah digunakan. Fitur ini juga menyebabkan hasPendingReceives() menganggap arrival sebagai "pending" selama container belum diinspeksi — sehingga invoice tetap berstatus "pending" meskipun semua barang sudah diterima.

Yang dihapus:

  • Route POST incoming-containers/{container}/inspect
  • Method IncomingArrivalController::inspectContainer()
  • Tipe ContainerRow di Form.vue
  • Blok form container + tombol add/remove
  • Blok tabel container di Show.vue
  • Pengecekan containers.inspection di hasPendingReceives()
  • Parameter containers dari eager load
